# Report / 财务接口本地调试切换说明

> 接口地址已**集中到 `src/services/apiTarget.ts`**，支持 **生产 / 本地接口1 / 本地接口2** 三套地址。
> 默认对接生产；本地联调时**无需改任何 service 文件**，运行时切换即可，提交代码前也不用再切回（默认值就是生产）。

---

## 一、地址配置

`src/services/apiTarget.ts`：

```ts
const DEFAULT_API_TARGET: ApiTarget = 'prod'; // 默认目标（提交代码时保持 prod）

export const API_BASE_URLS: Record<ApiTarget, string> = {
  prod: `${process.env.BASE_URL}`,
  local1: 'http://12.18.1.36:8085/oms',
  local2: 'http://10.162.250.167:9000/oms',
};
```

- 新增环境：在 `ApiTarget` 类型和 `API_BASE_URLS` 里各加一行即可。
- 两个本地地址都带 `/oms` 上下文（已实测：不带 `/oms` 会 500 / 404）。

---

## 二、运行时切换（推荐，不用重启 dev server）

打开浏览器控制台（F5 后执行）：

```js
window.__api.set('local1');   // 切到本地接口1：http://12.18.1.36:8085/oms
window.__api.set('local2');   // 切到本地接口2：http://10.162.250.167:9000/oms
window.__api.set('prod');     // 切回生产
window.__api.get();           // 查看当前目标
window.__api.current();       // 查看当前实际地址
window.__api.urls;            // 查看所有地址
window.__api.reset();         // 清除本地选择，回到 DEFAULT_API_TARGET
```

- 切换后页面会**自动刷新**，选择保存在 `localStorage`（key：`oms_api_target`），刷新/重启 dev server 后仍生效。
- 控制台会打印当前接口地址，方便确认。
- `window.__api` 只在非生产构建（`NODE_ENV !== 'production'`）挂载，线上不受影响。

---

## 三、跟随切换的接口

所有通过 `AxiosRequest` / `createRequest` 创建的实例，地址写成函数 `() => getOmsBaseUrl()`，每次请求时解析，因此**运行时切换立即生效**：

| 文件 | request 实例 | 对应页面/功能 |
|------|--------------|---------------|
| `managementReportApi.ts` | `omsRequest` | 管报数据查询（type 1~11）、沃尔玛山姆、U9 应收单、京东费用、天猫超市 |
| `managementReportApi.ts` | `billRequest` | 各渠道月账单（生成/上传/下载） |
| `channelExtendCostApi.ts` | `channelExtendCostRequest` | 渠道推广费用 |
| `channelExtendCostApi.ts` | `costCategoryStatLocalRequest` | 渠道推广费用分类统计 |
| `financeUnitCostApi.ts` | `financeUnitCostRequest` | 成本核算 |
| `financeApi.ts` | `financeRequest` / `getFinanceBaseUrl()` | 财务模块（数据执行、上传、下载） |

页面里拼接 `href` / `action` 的地址，统一用 `getFinanceBaseUrl()`（Finance 模块）或 `getOmsBaseUrl()`，不要再用固定的 `FINANCE_BASE_URL` 常量。

> 未纳入统一切换：`invoiceApi.ts`（`12.18.1.12`）、`salesmanBillCheckApi.ts`、`userApi.ts`（走 `USER_AUTH_BASE_URL`）；需要时按 `apiTarget.ts` 的方式接入。

---

## 四、代码里写死地址的写法已废弃

以前每个 service 顶部「生产一行 + 本地注释一行」的方式已移除，不要再使用：

```ts
// ❌ 已废弃
// const xxxRequest = createRequest(`http://12.18.1.36:8085/oms/xxx`, ...);

// ✅ 现在统一
const xxxRequest = createRequest(() => `${getOmsBaseUrl()}/xxx`, ...);
```

---

## 五、提交前自查

由于默认值固定为 `prod`，正常情况下无需切换即可提交。仍建议检查是否有新代码写死了地址：

```bash
grep -rn "12\.18\|10\.162\|localhost:8085" src --include='*.ts' --include='*.tsx' \
  | grep -v "src/services/apiTarget.ts"
```

结果应仅剩注释或与地址切换无关的内容；新地址请统一加到 `apiTarget.ts`。
